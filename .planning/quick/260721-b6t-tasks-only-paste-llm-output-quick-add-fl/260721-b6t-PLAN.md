  <action>
Create `frontend/src/lib/tasksPrompt.ts` with three exports.

1. `export const TASKS_PROMPT: string` — a SHORT prompt (target 12–20 lines). It describes ONLY the task output style: `title` (required), `priority` (`high`|`medium`|`low`), `due_date` (ISO 8601 datetime, e.g. `2026-07-22T09:00:00Z`), `description`, `estimated_minutes` (integer). It instructs the LLM to output a bare JSON array of task objects and nothing else.
   MUST NOT mention: goals, routines, habits, milestones, `external_key`, `goal_key`, or `schema_version` — the app supplies all of those. Do not restate the full ingest schema; this is deliberately the anti-`INGEST_PROMPT`.

2. `export function slugKey(title: string): string` — deterministic, synchronous, no crypto/async:
   - slug = lowercase, non-alphanumerics collapsed to `-`, leading/trailing `-` trimmed, truncated to 60 chars
   - suffix = short stable hash of the ORIGINAL trimmed title (FNV-1a 32-bit or djb2, base36, ~6 chars) so two titles that slugify identically don't collide
   - return `` `qa-${slug || "task"}-${suffix}` `` — stays well inside the 200-char `external_key` limit
   Same input → same output, always. Do NOT use `crypto.subtle` (async) or `Date.now()`/`Math.random()`.

3. `export function normalizeTasksInput(raw: string): { ok: true; payload: unknown } | { ok: false; error: string }` — a pure function, no React, no fetch:
   - strip a leading ```` ```json ```` / ```` ``` ```` fence and a trailing ```` ``` ```` fence (tolerate the language tag being `json`, `JSON`, or absent), then `.trim()`
   - `JSON.parse` inside try/catch → on throw return `{ ok: false, error: "Couldn't read that as JSON — paste just the JSON output from the LLM." }`
   - accept EITHER a bare array of task objects OR an object with a `tasks` array; anything else → friendly error
   - for each item: require a non-empty string `title`; pick ONLY the allowlisted `TaskImport` fields (`goal_key`, `title`, `priority`, `due_date`, `description`, `list_name`, `parent_list_name`, `estimated_minutes`) and drop everything else; use the item's `external_key` if it is a non-empty string, otherwise `slugKey(title)`; omit optional fields that are `undefined`/`null` rather than sending nulls
   - empty resulting list → `{ ok: false, error: "No tasks found in that paste." }`
   - success → `{ ok: true, payload: { schema_version: "1.0", tasks } }`

Error strings should match the friendly tone of `Ingest.tsx`'s `"Invalid JSON — check your payload and try again."`.
