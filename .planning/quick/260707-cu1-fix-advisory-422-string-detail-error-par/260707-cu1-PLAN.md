<objective>
Fix two independent, live-confirmed bugs in the advisor sync flow.

Purpose:
- Bug 1: `parse422` in the frontend crashes (TypeError on `.map()`) when the backend sends a plain-string 422 `detail` (business-logic errors like "unknown goal external_key: xyz"). The crash is swallowed by an outer catch, replacing the real, actionable error with a misleading "check your connection" message. Both the string shape (business validation) and the array shape (FastAPI pydantic validation) are real and must both be handled.
- Bug 2: The exported Advisor Brief omits each goal's `external_key`. The external LLM advisor therefore invents slug-style keys, which fail backend validation ("unknown goal external_key: ...") on every write-back. Rendering the real key lets the advisor copy it verbatim.

Output: Shape-aware `parse422` plus a new `external_key` line in the brief, both covered by tests.
</objective>

```typescript
function parse422(detail: ValidationError[]): string[] {

}
```
