# Phase 17 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none |
| Preset | not applicable |
| Component library | none (custom React components, hand-rolled CSS) |
| Icon library | lucide-react (existing dependency — `ArrowLeft`, `GripVertical`/drag-handle icon, etc.) |
| Font | System stack: `-apple-system, BlinkMacSystemFont, "Segoe UI", sans-serif` (body, all phase-17 surfaces). Georgia serif is reserved for the Today page's hero display headings only and is untouched by this phase. |

**shadcn gate decision:** `components.json` does not exist; no `tailwind.config.*`/`postcss.config.*` exist either. This codebase has used hand-rolled CSS custom properties (`frontend/src/styles.css`) consistently across all 16 prior phases (Task rows, Drawer, FAB, Organize workspace, Update Loop UI, Now view, Tasks card grid, Group tile grid). Introducing shadcn now would require adopting Tailwind for the first time — a full design-system migration with zero relationship to this phase's actual scope (adding parent/child nesting + drag-and-drop to two already-styled pages). RESEARCH.md's own stack decision for this phase is scoped to a single frontend-only dependency (`@dnd-kit/*`, per D-12) and explicitly does not propose a component-library change. Per CLAUDE.md ("no unsolicited refactors — fix what I ask, don't clean up surrounding code"), this contract keeps `Tool: none` and extends the existing CSS-variable system. Registry safety gate: **not applicable**.

## Spacing Scale

Declared values (must be multiples of 4) — reused verbatim from the existing `styles.css` system, no new tokens introduced:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-text gaps (drag handle icon, badge internal padding) |
| sm | 8px | Row internal gaps (existing `.task-row`, `.timeline-row` pattern); gap between drag handle and row content |
| md | 16px | Drawer field gaps (`.drawer-body` gap, existing); vertical rhythm between parent row and its children container |
| lg | 24px | **Subtask indent** — the one level of nesting (D-01) indents a child row 24px from its parent's left edge, on both the Today timeline and the Tasks page |
| xl | 32px | Not used by this phase |
| 2xl | 48px | Not used by this phase |
| 3xl | 64px | Not used by this phase |

Exceptions:
- **44×44px minimum touch target** on the drag-handle icon (icon-only affordance, no visible label) — matches WCAG 2.5.5 and this project's existing 44–48px minimum row-height convention (`.task-row` `min-height: 48px`, `.milestone-row` `min-height: 44px`). The visible icon may render smaller (e.g. 16–20px `lucide-react` icon) but its hit area must be padded to 44px.
- No other exceptions.

## Typography

Reused verbatim from the existing type scale in `styles.css` — this phase introduces **no new font sizes**.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 | 1.5 |
| Label (meta/secondary) | 14px | 400 | 1.4 |
| Badge / small | 12px | 500 | 1.2 |
| Heading | 20px | 600 | 1.2 |

**Weight declaration:** exactly 2 weights are used for new UI in this phase — **400 (regular)** for body/title text, **600 (semibold)** for headings and the "Subtask of" field label. The 500-weight badge style (12px/500, e.g. `.priority-badge`, `.organize-count`) is a pre-existing exception inherited unchanged from prior phases (not introduced here, not to be expanded further).

Applied to new phase-17 elements:
- Parent/child task and subtask titles → Body (16/400/1.5), same as existing `.task-row-title`/`.tasks-card-title`.
- Subtask progress badge ("2/3") → Badge/small (12/500/1.2), same visual weight as `.organize-count`.
- "Subtask of" drawer field label → Label style (14/600 — matches existing `.drawer-field label` which is already 14px/600).

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `var(--bg)` `#0f172a` | Page background (Today, Tasks) |
| Secondary (30%) | `var(--surface)` `#1e293b` | Cards, drawer, rows, badge backgrounds, nested-children container background |
| Accent (10%) | `var(--accent)` `#6366f1` | See explicit reserved-for list below |
| Destructive | `var(--destructive)` `#ef4444` | Existing task-delete action + error text only — **no new destructive action is introduced by this phase** |

**Accent reserved for** (explicit list — carries forward existing uses + adds phase-17-specific uses):

*Existing (unchanged):*
1. Primary CTA buttons (`.btn-save`, `.organize-primary-button`)
2. Active/selected state (active filter tab underline+text, active list chip)
3. Checkbox `accent-color` (`.task-checkbox`)
4. Progress bar fill (`.progress-bar-fill`)

*New, this phase:*
5. **Nest drop-target highlight** — while dragging a row over another row's center band (nest intent, per D-03/Pattern 3), the target row gets an accent-tinted background `rgba(99, 102, 241, 0.12)` + `1px solid var(--accent)` border — mirrors the existing `.organize-planned-content` treatment (`border-left: 3px solid #818cf8; background: rgba(99, 102, 241, 0.1)`).
6. **Reorder insertion line** — while dragging over the gap between two rows (reorder intent, per D-03), a 2px horizontal bar in `var(--accent)` renders at the insertion point.
7. **Drag handle icon** — `var(--text-secondary)` at rest, `var(--accent)` on hover/active-drag (mirrors `.organize-grip` → hover-to-accent pattern already used elsewhere).

**Explicitly NOT accent:** the subtask progress badge ("2/3", D-06) uses **neutral/secondary** styling — `background: var(--border)`, `color: var(--text-secondary)` — matching the existing `.organize-count` pattern, not the accent-tinted `.priority-badge` pattern. This keeps the accent reserved-for list from sprawling into a purely informational element.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | None new — this phase adds a field to the existing TaskDrawer, saved via the existing "Save Task" button (`.btn-save`); no new page-level or primary CTA is introduced. |
| Empty state heading | Not applicable — the subtask progress badge only renders when a parent has ≥1 child (D-06); there is no new empty-state screen in this phase. |
| Empty state body | Not applicable (see above). |
| Error state 1 (nest rejected — target already nested) | "Can't nest here — that task is already a subtask. Only one level of nesting is supported." (frontend-friendly rendering of the backend's 422 `"Cannot nest under a task that is itself a subtask (one level only)"`) |
| Error state 2 (nest rejected — source already has children) | "Can't nest here — that task already has subtasks of its own." (frontend-friendly rendering of the backend's 422 `"Cannot nest a task that already has subtasks (one level only)"`) |
| Destructive confirmation | None new. Nesting and un-nesting are explicitly non-destructive, reversible drag actions (D-07: no completion propagation; D-10: dragging to empty space cleanly clears `parent_task_id`) — no confirmation dialog per CONTEXT.md decisions. The existing task-delete confirmation modal (`.confirm-modal`, unchanged) continues to apply only to actual task deletion, which this phase does not modify. |

**New field copy (TaskDrawer "Subtask of" — D-11):**
- Field label: `Subtask of` (14px/600, matches existing `.drawer-field label` style)
- No-parent option (mirrors `GoalSelect`'s exact `"No goal"` convention): `No parent (top-level task)`
- Options list: populated from all tasks excluding (a) the task being edited itself, (b) any task that already has a parent (a child cannot become a parent, per D-01) — same exclusion logic pattern as `GoalSelect`'s active-goals filter.

**New accessibility copy:**
- Drag handle `aria-label`: `Drag to reorder or nest "{task title}"`
- Subtask progress badge `aria-label`: `{done} of {total} subtasks complete`
- Collapse/expand toggle `aria-label` (if user manually collapses a group past the D-09 expanded-by-default state): `Collapse subtasks of "{parent title}"` / `Expand subtasks of "{parent title}"`

## Interaction & State Notes (supplementary — not in base template, required for this drag-and-drop phase)

| State | Visual Treatment |
|-------|-------------------|
| Row being dragged (source) | Reduce opacity to `0.5` (matches existing `.timeline-row--past` convention) while `@dnd-kit` renders the drag overlay; no layout shift in the origin position until drop resolves. |
| Row hovered with "nest" intent | Accent-tinted background + border (see Color → item 5). Row corners keep existing `border-radius` per surface (8px timeline rows / 10px cards). |
| Gap hovered with "reorder" intent | 2px accent insertion line (see Color → item 6); no background tint on either adjacent row. |
| Drop in empty space (D-10, un-nest) | No highlight state needed — absence of any droppable target is itself the signal; on drop, child row animates back to top-level position (reuse existing `transition: opacity 150ms ease-out` timing already used on `.tasks-card`). |
| Parent row with children | Subtask progress badge renders inline after the title (12px/500, neutral styling, see Color section); children render in a `24px`-indented container directly beneath, **expanded by default** (D-09). |
| Nesting/un-nesting rejected (422) | Inline error text under the affected row, `12px`, `var(--destructive)` — same treatment as existing `.task-row-error` / `.tasks-card-error` (do not use a modal/toast for this — matches the project's existing inline-error convention on TaskCard/TaskRow). |
| Reduced motion | All new transform/opacity transitions respect `prefers-reduced-motion: reduce` (existing global pattern already applied to `.tasks-card`, `.momentum-ring-progress`, `.organize-task-card`) — extend the same media query block to cover new drag-transition rules. |
