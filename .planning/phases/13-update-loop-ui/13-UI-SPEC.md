# Phase 13 — UI Design Contract

> Visual and interaction contract for the Update Loop UI. Generated by gsd-ui-researcher.
> This phase ADDS to existing Today tab and Settings page — it must match the established
> inline-style pattern exactly. No new component library is introduced.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none — custom inline-style CSS variables |
| Preset | not applicable |
| Component library | none (custom pattern: CSS class + inline style override) |
| Icon library | lucide-react (already used via existing AgendaItem / Organize page SVGs) |
| Font | -apple-system, BlinkMacSystemFont, "Segoe UI", sans-serif (from body in styles.css) |

**Pattern rule:** All new components must follow the existing idiom:
- Named CSS classes in `styles.css` for structural/reusable rules
- Inline `style` props for one-off overrides and dynamic values
- CSS custom properties (`var(--bg)`, `var(--surface)`, `var(--accent)`, `var(--border)`, `var(--text)`, `var(--text-secondary)`, `var(--destructive)`) — never hard-coded hex inside TSX

---

## Spacing Scale

Declared values — multiples of 4, consistent with existing codebase (`.page` uses 32px top/16px side, sections `marginBottom: 24`, drawer body `gap: 16`):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, badge padding, inline label gaps |
| sm | 8px | Compact element spacing, checkbox-to-label gap |
| md | 16px | Default element spacing, drawer body gap, card padding |
| lg | 24px | Section `marginBottom`, between-card vertical gap |
| xl | 32px | Page top padding, major layout breaks |
| 2xl | 48px | Empty state padding-top |
| 3xl | 64px | Not used in this phase |

Exceptions:
- Touch targets (checkbox, confirm/dismiss buttons): minimum height 44px — matches `.milestone-row` min-height pattern
- Update input row: `minHeight: 52px` to accommodate phone keyboard ergonomics (slightly larger than standard 48px task row)
- Candidate list items: `minHeight: 48px` — matches `.task-row` min-height

## Typography

Exactly 4 sizes, 2 weights. The codebase contains a 13px section-label pattern in `styles.css`; for Phase 13 new components that usage is collapsed to 12px (see note below).

| Role | Size | Weight | Line Height | Usage |
|------|------|--------|-------------|-------|
| Heading | 20px | 600 | 1.2 | `.page-title` and `.drawer-title` — reused verbatim, not new |
| Body | 16px | 400 | 1.5 | Update input placeholder, candidate titles, rollup item titles |
| Label | 14px | 400 | 1.5 | Candidate subtitles, rollup counts, helper text under inputs, check-in toggle label, loading states |
| Label-bold | 14px | 600 | 1.5 | Status text, timestamps |
| Secondary/helper | 12px | 400 | 1.5 | Error text below inputs, helper hint text, rollup heading (uppercase), candidate meta (time/date) |

> **Phase-13 normalization note:** `styles.css` uses `fontSize: 13` for `SECTION_LABEL_STYLE` in existing Settings.tsx components. Phase 13 new components use 12px for all secondary/helper/meta text rather than 13px. This is a deliberate normalization for new surfaces only — do NOT change the 13px value in any existing component.

Section label style for new check-in section (Phase-13 normalized):
- `fontSize: 12, fontWeight: 600, color: "var(--text-secondary)", textTransform: "uppercase", letterSpacing: "0.05em"`

## Surface Inventory — New Components

Four new UI surfaces. Each is described with layout, states, and class names to add to `styles.css`.

### 1. Quick-Update Input Box (Today tab, above FocusBanner)

**Placement:** Renders as the first element inside `.page` on Today, above `<FocusBanner>`. Always visible.

**Layout:**
```
[ textarea or single-line input            ] [Submit]
  "What got done? e.g. finished standup"
```

- Container: `div.update-input-row` — `display: flex; gap: 8px; marginBottom: 16px; alignItems: flex-end`
- Input: `textarea.update-input` — `flex: 1; minHeight: 52px; maxHeight: 120px; resize: none; background: var(--bg); border: 1px solid var(--border); borderRadius: 6px; color: var(--text); padding: 8px 12px; fontSize: 16px; fontFamily: inherit`
  - Phase-13 normalization: `padding: 8px 12px` (not `8px 10px` — 10 is not a multiple of 4)
- Use `<textarea>` (not `<input type="text">`) so phone keyboard dictation microphone appears on iOS/Android
- Placeholder text: `"What got done? e.g. finished standup"`
- Submit button: `button.btn-save.btn-save--inline` — `padding: 12px 16px; height: 44px; borderRadius: 8px; flexShrink: 0; fontSize: 14px`
  - Phase-13 normalization: `padding: 12px 16px` (not `10px 16px` — 10 is not a multiple of 4); `fontSize: 14px` (not 15px — 15 is not in the 4-size scale)
- Button label (idle): `"Log update"`
- Button label (submitting): `"Logging…"` with `disabled` + `opacity: 0.6`
- On successful `applied` response: clear textarea, show inline success flash `"Done"` for 1.5s beside the button
- On `ambiguous` or `no_match`: do NOT clear textarea; transition to candidate confirmation flow (Surface 2)
- On network error: show error text below input (12px, `var(--destructive)`)

**States:** idle | submitting | success-flash | error

### 2. Candidate Confirmation Flow (inline on Today tab, replaces input row when ambiguous/no_match)

**Trigger:** Backend returns `status: "ambiguous"` or `status: "no_match"` from `POST /updates/resolve`.

**Layout:** Replaces the update-input-row with a disambiguation card. Input text is retained in the textarea (user may edit and resubmit).

```
[ Amber notice banner ]
  "Multiple matches found — pick the right one:"
  or "No exact match — did you mean one of these?"

[ Candidate list ]
  [ candidate title           time/date ]  [Confirm match]  [Skip]
  [ candidate title           time/date ]  [Confirm match]  [Skip]

[ text button: "None of these — dismiss" ]
```

- Wrapper: `div.candidate-card` — `background: var(--surface); border: 1px solid var(--border); borderRadius: 12px; padding: 16px; marginBottom: 16px`
- Notice banner (amber): reuse `.organize-notice` CSS class — `borderColor: rgba(245,158,11,0.28); background: rgba(245,158,11,0.08); color: #fbbf24`
  - Ambiguous copy: `"Multiple matches — pick the right one:"`
  - No-match copy: `"No exact match — did you mean:"`
- Candidate row: `div.candidate-row` — `display: flex; alignItems: center; gap: 8px; padding: 8px 0; borderBottom: 1px solid var(--border); minHeight: 48px`
- Candidate title: 16px / 400 / `var(--text)`
- Candidate meta (time or "today"): 12px / 400 / `var(--text-secondary)` — right-aligned `flex-shrink: 0`
  - Phase-13 normalization: 12px (not 13px — collapsed to the secondary/helper size)
- "Confirm match" button: `button.btn-candidate-confirm` — `padding: 8px 12px; background: var(--accent); color: #fff; border: none; borderRadius: 6px; fontSize: 14px; cursor: pointer`
  - Phase-13 normalization: `padding: 8px 12px` (not `6px 12px` — 6 is not a multiple of 4)
- "Skip" button: `button.btn-candidate-skip` — `padding: 8px 12px; background: none; color: var(--text-secondary); border: 1px solid var(--border); borderRadius: 6px; fontSize: 14px; cursor: pointer`
  - Phase-13 normalization: `padding: 8px 12px` (not `6px 12px` — 6 is not a multiple of 4)
- Dismiss link: `button.btn-text-accent` (existing class) — `"None of these — dismiss"` — calls `dismiss()` which clears state and textarea
- After Confirm match: re-call `POST /updates/resolve` with the confirmed `task_id` or `block_id`; on success show the same `"Done"` flash and clear; no modal

**Layout:**

  Day Rollup
  3 completed  •  2 slipped
  ---
  [x] Standup call           completed
  [x] Email review           completed
  [ ] Dentist appointment    slipped

- Container: `div.rollup-card` — `background: var(--surface); borderLeft: 3px solid var(--accent); borderRadius: 6px; padding: 16px; marginBottom: 16px`
- Heading: `p.rollup-heading` — `fontSize: 12px; fontWeight: 600; color: var(--text-secondary); textTransform: uppercase; letterSpacing: 0.05em; margin: 0 0 8px`; copy: `"Day Rollup"`
  - Phase-13 normalization: `fontSize: 12px` (not 13px — collapsed to secondary/helper size); `margin: 0 0 8px` (not `0 0 6px` — 6 is not a multiple of 4)
- Summary line: `p` — `fontSize: 14px; color: var(--text-secondary); margin: 0 0 12px` — `"{N} completed  •  {M} slipped"`
- Item list: `div.rollup-list` — `display: flex; flexDirection: column; gap: 0`

## Interaction Contracts

### Quick-update submit flow

```
user types in textarea
  → presses "Log update" button OR hits Enter (textarea is single-session so Enter submits)
  → button enters "Logging…" state (disabled)
  → POST /api/v1/updates/resolve { text }

  if status === "applied":
    → clear textarea
    → flash "Done" label for 1500ms
    → Today agenda optimistic-update: re-fetch tasks+blocks

  if status === "ambiguous" | "no_match":
    → textarea stays filled (user may edit and retry)
    → render CandidateCard below input row
    → button returns to idle (user may also resubmit edited text)

  if network error:
    → button returns to idle
    → show error text below textarea
```

### Candidate confirmation flow

```
user clicks "Confirm match" on candidate:
  → POST /api/v1/updates/resolve { text, confirmed_id: task_id|block_id }
  → on success: flash "Done", clear textarea, remove CandidateCard, re-fetch

user clicks "Skip" on one candidate:
  → remove that candidate from the displayed list only (local state)
  → if all skipped: show only dismiss link

user clicks "None of these — dismiss":
  → clear CandidateCard, clear textarea, no API call
```

### Rollup card render gate

- Call `isAfterWorkHours(workEnd)` (already implemented in frontend for Organize page)
- Derive completed/slipped from today's tasks+blocks that were scheduled for today:
  - completed: `item.completed === true`
  - slipped: `item.completed === false` AND item was scheduled for today (i.e., `item.isBlock || (item.dueDate === todayKey)`)
- Phase 12 decision: `completed=true` is ambiguous (done vs dropped) — rollup treats all `completed=true` as "completed" and shows all incomplete today-items as "slipped"
- Rollup is read-only; no actions on rows

### Settings check-in controls

- Toggle controls `checkinEnabled` boolean; time input controls `checkinTime` string (HH:MM)
- Both saved together via single `PATCH /api/v1/settings/check-in-time` (Phase 12 endpoint)
- Optimistic disable: while saving, both toggle and time input are `disabled`
- Saving persists across reboots via APScheduler SQLAlchemyJobStore (Phase 12 guarantee)
