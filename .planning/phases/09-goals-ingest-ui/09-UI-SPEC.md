## Interaction Contracts

### Goals Page

**Layout:** `.page` container, `.page-title` "Goals", filter tabs (Active / Archived), goal list rows, FAB for create.

**Goal list row:**
- Height: minimum 48px (matches `.task-row`)
- Content: goal title (16px/400), type badge (12px/500 pill), progress percent (14px/400, right-aligned)
- Progress bar: 8px tall, full width below title line, `--border` track, `--accent` fill, `border-radius: 4px`
- Tapping a row opens goal detail (in-page `selectedGoalId` state — no route change)

**Goal detail (in-page, replaces list):**
1. Back button (← arrow, lucide `ChevronLeft`, 22px) + goal title as heading
2. Progress section: percent label (14px/600) + progress bar (8px, `--accent` fill)
3. Milestones section header (14px/600, `--text-secondary`): "Milestones"
   - Each milestone: checkbox (24px, `accent-color: var(--accent)`) + title (16px/400)
   - "Add milestone" button: text button, 14px/400, `--accent` color, no background
4. Linked tasks section header: "Linked Tasks"
   - Each task row: render as `TaskRow` component; tapping opens `TaskDrawer`
5. Action row at bottom: "Complete Goal" (text link, `--accent`) | "Archive Goal" (text link, `--destructive`)

**GoalDrawer fields (create/edit):**
- Title (required): text input, placeholder "Goal title"
- Type (required): segmented-control (5 segments: Career / Life / Health / Learning / Financial) — existing `.segmented-control` class
- Description (optional): textarea, `min-height: 80px`, placeholder "Add context or description"
- Target date (optional): date input
- Save button: `.btn-save` — "Save Goal"
- Archive action (edit mode only): `.btn-delete` — "Archive Goal" — triggers confirm-modal before PATCH

**FAB:** existing `.fab` class, `+` icon (lucide `Plus`, 24px, white), bottom: 80px, right: 16px.

### GoalSelect (shared dropdown)

Native `<select>` element inside `.drawer-field`. Options:
- `<option value="">No goal</option>` (first, always present)
- One `<option>` per active goal (status === "active"), value = goal.id, text = goal.title

Applied in: TaskDrawer (after Priority field), RoutineDrawer (after Schedule field).

### Ingest Page

**Route:** `/ingest` — reached via "Import" button on Goals page (lucide `Upload` icon, 16px, placed in page header right side next to page-title).

**Layout:** `.page` container, `.page-title` "Import Data"

**Sections (top to bottom):**

1. **LLM Prompt section**
   - Section label (14px/600, `--text-secondary`): "LLM Prompt"
   - `<pre>` block containing the static prompt constant from `lib/ingestPrompt.ts`
   - Styling: `background: var(--surface)`, `border: 1px solid var(--border)`, `border-radius: 6px`, `padding: 12px`, `font-size: 14px`, `overflow-x: auto`, `white-space: pre-wrap`
   - "Copy prompt" button: inline text button (14px/400, `--accent`), positioned top-right of the `<pre>` block; uses `navigator.clipboard.writeText()`
   - On copy success: button text changes to "Copied!" for 2 seconds, then reverts

2. **Input section**
   - Section label: "Paste JSON or upload a file"
   - Textarea: full width, `min-height: 160px`, `resize: vertical`, `font-size: 14px`, `font-family: monospace`, placeholder "Paste your JSON payload here…"
   - File upload: `<input type="file" accept=".json">` styled as a secondary button (14px/400, `--text-secondary`, `border: 1px solid var(--border)`, `border-radius: 6px`, `padding: 8px 12px`)
   - File upload reads via `FileReader.readAsText()` into the same textarea state
   - "Run Preview" button: `.btn-save` width: auto (not full width), right-aligned, disabled + `opacity: 0.6` while `previewing === true`, label: "Run Preview" / "Previewing…"
   - JSON parse error (client-side, before API call): inline message below textarea in `--destructive`, 14px, e.g. "Invalid JSON: Unexpected token } at position 42"

3. **Preview results section** (conditional — renders after successful preview response)
   - Section label: "Preview" + entity counts summary (e.g. "3 goals · 5 tasks · 2 routines · 1 habit")
   - Four sub-groups: Goals, Tasks, Routines, Habits — each with a group header (14px/600) and item list
   - Each item row: entity title (16px/400) + action badge right-aligned
     - "create" badge: `rgba(16, 185, 129, 0.15)` background, `#10b981` text, 12px/500, pill shape (matching `.priority-badge`)
     - "update" badge: `rgba(99, 102, 241, 0.15)` background, `#6366f1` text, 12px/500, pill shape
   - If a group is empty (e.g. no habits), the group is omitted

4. **Confirm section** (conditional — renders only after preview results are present)
   - "Confirm Import" button: `.btn-save`, full width, disabled + `opacity: 0.6` while `confirming === true`
   - Label: "Confirm Import" / "Importing…"
   - On success: navigate back to `/goals` and trigger goals list refresh

5. **Validation error section** (conditional — renders on HTTP 422 from preview or confirm)
   - Section label: "Validation Errors" in `--destructive`, 14px/600
   - Error list: one item per FastAPI `detail[]` entry, 14px/400, `--destructive` color
   - Format: `tasks.2.due_date: invalid datetime`
   - Scrollable list, `max-height: 200px`, `overflow-y: auto`

### BottomNav (4th tab)

Tab order: Today | Tasks | Goals | Settings

Goals tab:
- Icon: `Target` from lucide-react, size 22
- Label: "Goals", 14px
- Active color: `var(--accent)`
- Inactive color: `var(--text-secondary)`
- Touch target: 44px minimum height (enforced by `minHeight: 44` in existing tabStyle)

### Destructive Actions

| Action | Trigger | Confirmation |
|--------|---------|-------------|
| Archive goal | "Archive Goal" `.btn-delete` in GoalDrawer (edit mode) | confirm-modal — title: "Archive goal?", body: "The goal will be hidden from the active list. You can restore it later.", buttons: "Archive" (`.btn-confirm-delete`) + "Cancel" (`.btn-cancel`) |
| Goal detail archive | "Archive Goal" text link in goal detail | Same confirm-modal pattern |

No hard delete in this phase. Archive is the only destructive action (D-03: archive = `PATCH /goals/{id}` with `status=archived`).
