## Component Inventory

### New: "Focus on:" Banner (`Today.tsx`)

- Source: CONTEXT.md D-08 — sticky banner above agenda in Today view
- Placement: between `<h1 className="page-title">` and the first `<DaySection>`
- Renders only when a pending top-scoring task exists; no render when list is empty (D-08)
- Structure:
  ```
  .focus-banner
    .focus-banner-label   "Focus on"        (14px, 600, --text-secondary)
    .focus-banner-title   {task title}      (16px, 400, --text)
    .focus-banner-meta    {goal name} · {priority badge}  (14px, --text-secondary)
  ```
- Visual: `background: var(--surface)`, `border-left: 3px solid var(--accent)`, `border-radius: 6px`, `padding: 12px`, `margin-bottom: 16px`
- No dismiss button in v2.0 (CONTEXT.md says dismiss behavior is Claude's discretion — omit for simplicity; banner refreshes on next page load)
- Data: fetched from `GET /guidance/next-best-task` (new endpoint per D-07)

### Extended: Settings Page (`Settings.tsx`)

- Add `stall_threshold_days` integer input field (D-11)
- Placement: new "Guidance" section after existing work-hours section
- Field label: "Stall threshold (days)" — 14px, 600, `--text-secondary`
- Input: same `.drawer-field input` style — `background: var(--bg)`, border `var(--border)`, 16px font
- Value: integer, 1–365, default 7
- No additional UI for `last_guidance_sent_date` — that is a backend-managed field, not user-editable

## Copywriting Contract

| Element | Copy |
|---------|------|
| Focus banner label | `Focus on` |
| Focus banner — no task | (banner not rendered — no empty state needed) |
| Focus banner loading | (render nothing while loading — no skeleton needed at this scale) |
| Settings field label | `Stall threshold (days)` |
| Settings field hint | `Goals with no task completions for this many days trigger a nudge. Default: 7.` |
| Settings save CTA | `Save Settings` (matches existing Settings page pattern) |
| Error: next-best-task fetch fails | Banner silently absent — do not surface fetch error to user |
| Stall nudge Pushover body | `Goal stalled: {title} — {N} days without a completion. Next: {most-urgent task title}.` (D-12, backend copy) |
| Daily brief goal snapshot line | `{goal title}: {progress}% — next: {task title}` (D-02, backend copy) |
| Brief TTS preamble for goals | `You have {N} active goals. Top goals: {goal 1 title}, {goal 2 title}.` (D-04, backend copy) |

No destructive actions in this phase. No confirmation dialogs required.

## States

### Focus Banner

| State | Behavior |
|-------|----------|
| Loading | Banner absent (no spinner — Today already shows agenda loading state) |
| Has top task | Render banner with task title + goal name + priority badge |
| No pending tasks | Banner not rendered |
| Fetch error | Banner not rendered (silent fail — guidance is supplementary, not critical) |

### Settings — Stall Threshold Field

| State | Behavior |
|-------|----------|
| Default (first load) | Show 7 |
| Edited | Show user-entered value |
| Invalid (non-integer, <1, >365) | Show red border (`--destructive`) + inline error text: `"Enter a number between 1 and 365."` |
| Saved | Existing settings success state (matches current settings save pattern) |

## Interaction Notes

- The "Focus on:" banner is read-only in Phase 11. Clicking it does NOT open TaskDrawer. That linkage is deferred — the banner is informational only.
- `stall_threshold_days` input follows the same save flow as `work_start_hour` / `work_end_hour` — part of the existing Settings form submit, not a separate save action.
- Accessibility: banner `role="region"` + `aria-label="Suggested focus"` for screen reader labeling.
